How everything is calculated

This page explains the exact logic behind every number in the report. All times are in business days (bd) — Monday to Friday only, weekends excluded. Data is pulled from Jira every morning at 8am and the report is republished automatically.

Foundations

Business days
Every duration in this report is measured in business days — Monday through Friday only. Weekends are excluded. A ticket that entered Phase 2 on a Friday and moved to Phase 3 the following Monday spent 1 business day in Phase 2.
Fiscal quarters (project44)
project44's fiscal year starts in February. Quarters are:
Q1 = Feb – Apr  |  Q2 = May – Jul  |  Q3 = Aug – Oct  |  Q4 = Nov – Jan
FY27 = 1 Feb 2026 – 31 Jan 2027. The OKR target quarter Q2 FY27 = May–Jul 2026.
Flow time vs total time
Active flow time = time spent actively progressing through Phases 1–5 only. Blocked and waiting statuses are excluded — this shows how fast work moves when it's actually moving.

Total flow time = active flow time plus any time spent in Blocked or Waiting statuses. This is the end-to-end wall clock from Phase 1 entry to Phase 5 exit.
How time in a phase is measured
Jira records a changelog entry every time a ticket changes status. The report reads the full changelog for each ticket and computes how many business days elapsed between each status transition. If a ticket moves back and forth between phases, all time in each phase is accumulated. Phase time for the current phase accumulates until today's date and is refreshed every morning.

Summary cards — Average days per phase

Each card shows two separate averages for a phase:
Final avg · N tickets
Tickets that have already exited this phase — their time in the phase is settled. The average updates whenever a ticket transitions out. A ticket that moved through Phase 3 in 5bd will permanently contribute 5bd to this average. Julia Domagala is excluded from averages as she is PM/reporter, not a builder.
Live avg · M tickets ↻
Tickets currently in this phase right now. Their time is still accumulating — the number grows every business day the ticket stays in that phase. Refreshed every morning from Jira. If the live avg is significantly higher than the final avg, tickets are getting stuck in this phase longer than historical ones did — a bottleneck signal.

Phase gate time chart

Shows the average number of business days from ticket creation to first reaching each phase. This is a cumulative measure — it answers "how long before a workflow typically hits this milestone?"

Calculation: For each ticket that reached Phase N, sum the business days spent in all prior phases (Not Started + Phase 1 + Phase 2 + … + Phase N−1). Average across all tickets that reached that phase.

Only PROMPT tickets are included. Only tickets that actually reached the phase are counted in that phase's average — a ticket that never entered Phase 5 is excluded from the Phase 5 bar.

Quarterly throughput chart

Counts PROMPT tickets that completed (reached Phase 7: Beta or General Availability) in each quarter.

Quarter assignment: A ticket is counted in the quarter of its last Jira status transition — i.e. when it was moved to Beta or GA. This is the completion date.

A ticket started in Q1 that completes in Q2 counts as Q2 throughput. This is intentional — it answers "what did the team ship in Q2?" regardless of when the work started. Each ticket is counted exactly once.

Pipeline intake chart — tickets entering Dev Ready per quarter

Counts PROMPT tickets that first reached Phase 4: Ready for Development in each quarter. Rising bars mean more builds are being handed to engineering.

Quarter assignment: A ticket is counted in the quarter it first entered Phase 4, using the exact date from the Jira changelog (pe field = phase entry dates). Each ticket counted once regardless of how many times it may have moved in and out of Phase 4.

Quarter-over-Quarter chart — avg days per phase

Shows how average phase times have changed across quarters, using the weekly snapshot history.

Calculation: Every week, a snapshot captures the average business days each active PROMPT ticket has spent in each phase. All snapshots within a quarter are averaged together to produce that quarter's bar. Quarters with more snapshots produce more reliable averages.

⚠ Q1 2026 (Feb–Apr) was the first batch of workflows — some were mid-flight when tracking started. Treat Q1 as a baseline, not a fair comparison. Q2 2026 onwards reflects full phase 1→5 journeys.

The two lines show active flow time (Phases 1–5 only) and total flow time (including blocked/waiting time) over the same period.

WIP snapshot chart — portfolio state at end of quarter

Shows how many PROMPT tickets were sitting in each phase at the end of each quarter, using the latest weekly snapshot from that quarter.

This answers "what did the team's in-flight portfolio look like at the close of Q2?" — useful for seeing whether work is piling up in any particular phase over time. Data starts from Q2 2026 when weekly snapshots began.

Velocity story chart

Two signals on one chart to tell the velocity story:

Green bars (left axis) — Completions per quarter: Count of PROMPT tickets that reached Beta or GA, assigned to the quarter of their completion date. Same logic as the Throughput chart.

Blue line — Avg active flow time: The active flow time reading from the latest weekly snapshot within each quarter. Reflects the speed of work in motion.

Purple line — Avg time to reach Ph4, excl. blocked: For tickets that have entered Phase 4 (Ready for Development), the cumulative business days spent in active phases only (Not Started + Ph1 + Ph2 + Ph3) before reaching Ph4. Assigned to the quarter the ticket first entered Ph4. A falling line means pre-engineering work is getting faster.

Red dashed line — Avg time to reach Ph4, incl. blocked: Same as above but includes all blocked and waiting time accumulated before Ph4. The gap between the red and purple lines represents the cost of blockages. If the gap widens, blocked time is increasing even if active work is speeding up.

The goal: bars rising, all lines falling. If purple and red lines converge, blocked time is reducing.

All-time programme chart — tickets by current phase

A simple snapshot of where every PROMPT ticket currently sits across the full build pipeline. Each ticket appears exactly once in its current Jira status. Updated every morning. This is not a trend — it's a live view of the whole portfolio's shape today.

Data source & refresh

All data comes from Jira filter #28132 via the Jira REST API, including full changelog history for every ticket. A scheduled task runs every morning at 8am, fetches the latest data, recomputes all phase times, and publishes the updated report to GitHub Pages and Confluence automatically.

The REPORT_DATE shown at the top of the report reflects when the Jira data was last computed — not the date the report is being viewed.
